# Ayodeji — The Possibility Engine

Evidence-based build plan, 8 September 2026. Audience: hiring teams and founders. Creative direction accepted by Ayodeji. This document records the accepted direction and implementation roadmap. The local implementation is now built; the status below records verification and remaining publication work.

## The experience

An impossible structure made from the actual systems Ayodeji has built occupies the opening viewport. It moves, separates and reorganizes as the visitor explores. Selecting a part reveals a real project and its underlying decisions. The spectacle and the evidence share the same objects.

Proposed opening copy: **I turn ambiguous problems into working AI products.** Supporting line: **Product judgment. Agent workflows. Systems that run.** These are draft positioning lines, not new job titles.

The opening always includes Ayodeji's name, a clear work action and contact access. No forced loading ritual, mandatory tour, scroll hijacking or hidden exit. The first impression should be extraordinary; the route to assessing the work should be obvious.

## What the research changed

## Art direction

- Ink-black space, acid-yellow emphasis, electric-blue structural passages and white type. Color separates interaction/state and scene changes; it must not become an arbitrary gradient wash.
- Oversized typography and precise, impossible geometry at architectural scale. Forms can pass through, invert and unfold without pretending to be physical objects.
- One signature moving structure per scene. Quiet evidence panels retain focus and readability.
- Actual product fragments and authored diagrams give the world its identity. Avoid generic robot imagery, decorative terminals and arbitrary particle fields.
- Navigation, project selection, detail surfaces, error states and mobile compositions belong to the same visual language.

## Animation choreography

| Moment | Planned movement | Functional purpose | Reduced-motion equivalent |
|---|---|---|---|
| First viewport | Slowly evolving geometric structure with restrained local response | Establish the portfolio's distinctive artifact immediately | Static composed structure |
| Project discovery | Structure separates into labelled project anchors | Reveal organization without a conventional card grid | Anchors visible immediately |
| Project selection | Selected geometry expands and resolves into its detail view | Preserve context across the transition | Immediate detail view with focus moved to its heading |
| Workflow inspection | Sequential branching, convergence and state changes | Explain the real mechanism | Step controls and complete static diagram |
| Return to overview | Reverse transformation into the original anchor | Make navigation spatially understandable | Return with focus restored to the initiating control |
| Pointer/touch | Small bounded depth/distortion response | Communicate that the artifact is operable | Standard hover/focus/pressed states |
| Evidence passages | Minimal motion and stable text | Let visitors assess claims and decisions | Identical readable content |

Pause offscreen work and when the tab is hidden. Touch interaction must not depend on hover. Motion controls, keyboard access and visible labels are part of the initial implementation.

## Implementation stages

### 1. Prove the opening and one project

Create a composition/motion study in the accepted visual world, then a working opening linked to one complete Skilladder case-study experience. Keep factual content in semantic HTML and isolate GPU/canvas work in a bounded client layer. Preserve existing URLs. A simple graphics fallback must contain all essential information.

Exit condition: the opening feels unmistakably authored; a new visitor can identify Ayodeji, open the project, inspect one credible artifact and reach contact using mouse, touch or keyboard.

### 2. Add the agent mechanism and platform story

Implement the Onboarding Engine walkthrough and Orderflow branching workflow. Give each an outcome, system and method layer, with source-grounded copy and a clear distinction between interactive illustration and recorded execution.

Exit condition: each flagship adds a different reason to hire Ayodeji. None relies on a tool-logo collection or unsupported outcome claim.

### 3. Extend through the portfolio

Rebuild Work, About, Skills and Contact inside the same world. Keep a compact, filterable project-family index and direct detail routes. Translate skills into evidence-linked capabilities. Add selected experiments only when their evidence status is clear.

Exit condition: no route falls back to the discarded visual identity; CV, metadata, social previews, navigation and contact still work.

### 4. Verify and prepare publication

Inspect desktop and mobile together, then fix material issues in one batch and confirm once. Test project transitions, browser Back, deep links, keyboard focus, touch, reduced motion, loading/error states and graphics failure. Run existing lint/build checks and targeted behavioral tests for the navigation/interactive state. Use synthetic data for all demonstrations.

Performance targets for implementation: responsive interaction on a modest phone, stable text/layout during graphics initialization, no render loop while hidden, and graphics quality scaled to device capability. Measure actual behavior before claiming a frame rate or score.

Exit condition: working, reviewable local build with source-grounded case studies, complete fallback, verified routes and a documented design system. Deployment is a separate explicit action.
